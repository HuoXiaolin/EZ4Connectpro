# 深信服 VPN 工作台

工作台管理 aTrust 和 EasyConnect 配置。左侧可按协议筛选，也可搜索配置名、协议或网关。选中配置只切换右侧详情。网关、连接状态、本机代理端口和活动日志都可在工作台查看。

在工作台新建、编辑和选择配置。选中配置后，可在「更多操作」重命名或删除。aTrust 的登录缓存和设备授信操作也在这里，授信操作在已有登录缓存时显示。

## 托盘状态与操作

- 关闭主窗口会隐藏到系统托盘，未连接时也会保留运行。单击托盘图标恢复主窗口；需要结束软件时，使用托盘右键菜单的「退出 EZ4Connectpro」。
- 图标右上角的黄点表示有线路正在连接、准备通道或重连。全部活动连接就绪后显示绿点，全部断开后恢复原图标。多条线路同时运行时，黄点优先提示尚未就绪的线路。
- 鼠标停留在托盘图标上可查看连接数量、线路名、状态和通道类型（TUN、本地代理或系统代理）。线路较多时显示摘要，完整列表在右键菜单查看。
- 右键展开一条线路可连接、取消、断开或在工作台查看。操作针对该线路，不受工作台当前选择影响。已连接线路还显示 SOCKS5 和 HTTP 端口。
- 右键菜单也提供断开全部、配置导入导出、新建线路、启动设置和打开日志。应用持有系统代理时才显示「释放本工具代理」。退出会先断开活动连接。

## 导入和导出配置

- 「文件 → 导入配置文件」读取 aTrust 或 EasyConnect 的 `.ini`，另存为一条线路。配置重名时加序号，代理端口与已有配置冲突时重新分配。
- 「文件 → 导出当前配置」备份当前选中的 `.ini`。导出包含已保存的账号和凭据。登录缓存、证书文件和全局启动设置单独存储。

## Windows 开机启动

在「设置 → 启动设置」开启开机启动，勾选需要自动连接的线路，支持多选。不勾选任何线路时仅启动软件。勾选静默启动时，软件在登录 Windows 后直接进入托盘。手动打开会显示工作台。线路编辑页只管理该线路的连接参数。

选中的线路各自建立连接并执行端口、网卡和路由冲突检查。不可用的线路会跳过并写入日志，其他线路继续启动。包含 TUN 线路时，软件会在发起连接前统一请求管理员授权，授权后保留全部开机线路选择。取消授权时只启动不需要 TUN 的线路。旧版单条线路选择会自动保留为多选列表中的一项。

启动设置显示 Windows 启动项的登记状态。旧启动项或便携 EXE 移动后，可用「保存并修复」重新登记当前路径。

## 浏览器访问内网页面

1. Windows 上选中配置，点击「连接 VPN」。便携版首次建立内网通道时需要 Windows 管理员授权，授权后自动继续连接。
2. 登录成功后，应用通过内置虚拟网卡应用网关下发的路由。工作台显示「内网分流已启动」后，在常用浏览器中输入原内网网址。
3. 自动路由会保留 Clash 等工具原有的系统代理。浏览器通过 Clash 访问时，目标内网流量需由 Clash 直连，才能命中本机的 VPN 路由。若规则将目标发给远端代理，系统路由无法接到该请求。

Windows 默认启用 TUN 和自动内网路由。可在「编辑配置 → 高级」直接切换「TUN 模式」。关闭 TUN 后，该配置使用本机代理。开启 TUN 并关闭「通用 → 连接后自动建立内网路由」后，可手动选择路由和 DNS 选项。

## 单点登录的两种浏览器方式

「临时浏览器配置」是 aTrust CAS 和 HTTPS OAuth2 的默认方式。应用打开本机支持的 Chrome、Edge、Firefox 或 Zen，使用独立的临时配置并自动接回票据。登录结束或取消时关闭该窗口并清理临时配置。

在登录弹窗可以改用「系统默认浏览器」。若希望某条连接每次都使用现有浏览器配置，可在该连接的「编辑配置 → 登录浏览器」中保存选择。首次使用系统默认浏览器时按以下步骤加载回传扩展。

1. 发起 aTrust CAS 或 HTTPS OAuth2 连接，在登录弹窗选择「系统默认浏览器」，点击「导出回传扩展」。
2. 在平时使用的浏览器配置加载刚导出的目录。Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`，开启开发者模式并选「加载已解压的扩展」。Firefox 或 Zen 打开 `about:debugging#/runtime/this-firefox`，选「临时载入附加组件」并打开目录内的 `manifest.json`。本地 Firefox 扩展未签名，重启浏览器后需要重新加载。 [Chrome 本地扩展加载说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world) · [Firefox 临时载入说明](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/)
3. 刷新应用打开的登录标签页，首次访问该 VPN 网关时允许扩展回传。若常用配置是浏览器的另一个用户，选「复制登录链接」，在那个用户配置里粘贴。

回传规则只绑定工作台打开的标签页和该次连接的网关。单次链接五分钟内有效。退出连接后，原链接无法向工作台提交票据。

## 配置与并行会话

- `Profile/DisplayName` 用作界面名称，可以用中文。重命名保留 INI 文件标识和登录缓存。已有深信服配置通过 `ZJUConnect/Protocol` 识别，无需重建。其他协议的旧配置文件保留在原目录，工作台会隐藏它们。
- 每条配置使用自己的认证流程、核心进程和代理端口。Windows 内置核心为每条开启 TUN 的配置分配独立网卡，网段互不重叠时可以并行。网关认证后若下发相同的虚拟 IP 或重叠的内网网段，应用会阻止新增连接。DNS 劫持一次由一条连接使用。若 Clash TUN 已占用相同的 Fake IP 网段，应用也会提示冲突。
- 同一配置的虚拟网卡被占用、TUN 与 TCP 隧道模式同时开启，或代理端口发生冲突时，应用会提示并阻止启动。关闭 TUN 的配置可通过各自的本机代理并行连接。使用原版 zju-connect 或其他系统时，工作台仍沿用单条 TUN 连接的限制。
- `--profiles-dir` 可指向独立的配置目录，也可用 `--config-path` 临时指定一个 INI。

## Windows 进程名称

主窗口标为「主界面 - EZ4Connectpro」。每条活动线路使用独立的「EZ4Connectpro · VPN 连接核心」进程；「EZ4Connectpro · 运行文件管理」等待主界面结束后清理便携运行文件。

便携启动器完成交接后退出，运行文件管理与 VPN 核心由主界面创建，归属同一棵进程树。它们仍各自拥有独立 PID，便于区分界面、连接和清理功能。
