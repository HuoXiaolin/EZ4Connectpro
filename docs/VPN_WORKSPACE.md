# 深信服 VPN 工作台

工作台管理 aTrust 和 EasyConnect 配置。左侧可按协议筛选，也可搜索配置名、协议或网关。选中配置只切换右侧详情。网关、连接状态、本机代理端口和活动日志都可在工作台查看。

在工作台新建、编辑和选择配置。选中配置后，可在「更多操作」重命名、删除或清理登录缓存。aTrust 的「打开资源页」和「授信设备管理」直接显示在主界面，连接中即可使用。设备管理需要先成功登录一次；清理登录缓存、重命名和删除配置仍需先断开该线路。

## 托盘状态与操作

- 关闭主窗口会隐藏到系统托盘，未连接时也会保留运行。单击托盘图标恢复主窗口；需要结束软件时，使用托盘右键菜单的「退出 EZ4Connectpro」。
- 图标右上角的黄点表示有线路正在连接、准备通道或重连。全部活动连接就绪后显示绿点，全部断开后恢复原图标。多条线路同时运行时，黄点优先提示尚未就绪的线路。
- 鼠标停留在托盘图标上可查看连接数量、线路名、状态和通道类型（TUN、本地代理或系统代理）。线路较多时显示摘要，完整列表在右键菜单查看。
- 右键展开一条线路可连接、取消、断开或在工作台查看。操作针对该线路，不受工作台当前选择影响。已连接线路还显示 SOCKS5 和 HTTP 端口。
- 右键菜单也提供断开全部、配置导入导出、新建线路、启动设置和打开日志。应用持有系统代理时才显示「释放本工具代理」。退出会先断开活动连接。

## 导入和导出配置

- 「文件 → 导入配置文件」读取 aTrust 或 EasyConnect 的 `.ini`，另存为一条线路。配置重名时加序号，代理端口与已有配置冲突时重新分配。
- 「文件 → 导出当前配置」备份当前选中的 `.ini`。导出包含已保存的账号和凭据。登录缓存、证书文件和全局启动设置单独存储。

## Windows 开机启动

在「设置 → 启动设置」开启开机启动，勾选需要自动连接的线路，支持多选。不勾选任何线路时仅启动软件。勾选静默启动时，软件在登录 Windows 后直接进入托盘。手动打开会显示工作台。线路编辑页只管理该线路的连接参数。

选中的线路各自建立连接并执行端口、网卡和路由冲突检查。不可用的线路会跳过并写入日志，其他线路继续启动。包含 TUN 线路时，软件会在发起连接前统一请求管理员授权，授权后保留全部开机线路选择。取消授权时只启动不需要 TUN 的线路。旧版单条线路选择会自动保留为多选列表中的一项。

启动设置显示 Windows 启动项的登记状态。旧启动项或便携 EXE 移动后，可用「保存并修复」重新登记当前路径。

## 浏览器访问内网页面

1. Windows 上选中配置，点击「连接 VPN」。便携版首次建立内网通道时需要 Windows 管理员授权，授权后自动继续连接。
2. 登录成功后，应用通过内置虚拟网卡应用网关下发的路由。工作台显示「内网分流已启动」后，在常用浏览器中输入原内网网址。
3. 自动路由会保留 Clash 等工具原有的系统代理。浏览器通过 Clash 访问时，目标内网流量需由 Clash 直连，才能命中本机的 VPN 路由。若规则将目标发给远端代理，系统路由无法接到该请求。

Windows 默认启用 TUN 和自动内网路由。可在「编辑配置 → 高级」直接切换「TUN 模式」。关闭 TUN 后，该配置使用本机代理。开启 TUN 并关闭「通用 → 连接后自动建立内网路由」后，可手动选择路由和 DNS 选项。

## 单点登录的两种浏览器方式

「临时浏览器配置」是 aTrust CAS 和 HTTPS OAuth2 的默认方式。应用打开本机支持的 Chrome、Edge、Firefox 或 Zen，使用独立的临时配置并自动接回票据。手动网页认证完成并连接成功后，在同一个窗口打开网关的官方资源页，可以查看该账号可访问的应用；窗口关闭或退出软件时清理临时配置。取消登录会直接关闭临时窗口。

资源页复用本次连接获得的网关会话，不再次使用已消费的 CAS 票据。关闭资源页不影响已建立的 VPN 连接。后台恢复成功时保持静默，不为资源页额外弹窗。

连接成功后可随时点击主界面的「打开资源页」。即使本次连接没有弹出登录浏览器，也会使用当前线路的会话打开官方应用资源页。临时浏览器方式会复用已打开的资源窗口或新建独立窗口；系统默认浏览器方式通过回传扩展恢复页面会话。未连接时该按钮不可用。

Windows 上的 Chrome / Edge 登录会将该线路的 Cookie 加密保存，供下次启动使用。VPN 登录缓存仍有效时直接连接；需要重新获取票据时，先用保存的 CAS 会话在后台尝试恢复，成功后不显示登录窗口。最多尝试 15 秒，未能恢复或需要账号、验证码等验证时，再打开可见浏览器。Firefox / Zen 目前仍使用原有的交互登录方式。

旧版已经删除的浏览器登录记录无法恢复，因此升级后第一次需要网页认证时，仍需完成一次登录以建立记录。该机制保留服务器已签发的会话，服务端撤销或强制过期后仍需按要求验证；不会把授信状态当作登录凭据。已用本地模拟 CAS 验证跨应用进程恢复和失效回退，实际网关在电脑重启后的行为需现场验证。

官方客户端使用的持久 `passportToken` 恢复流程仍在核对，本版尚未完成该原生机制，不能将以上浏览器会话恢复等同于官方的授信设备免登录。已确认的流程、验证结果和待核对事项见[原生免登录核对记录](ATRUST_RESTORE.md)。

记录只来自本工具创建的临时配置，使用当前 Windows 用户的 DPAPI 加密，并绑定线路文件位置和 VPN 网关。不同线路独立保存，不读取常用浏览器的 Cookie，不保存输入的密码，也不随 INI 导出。使用「更多操作 → 清理登录缓存」会同时删除该线路保存的浏览器记录。临时浏览器的完整用户目录仍在关闭时清理。

在登录弹窗可以改用「系统默认浏览器」。若希望某条连接每次都使用现有浏览器配置，可在该连接的「编辑配置 → 登录浏览器」中保存选择。首次使用系统默认浏览器时按以下步骤加载回传扩展。

1. 发起 aTrust CAS 或 HTTPS OAuth2 连接，在登录弹窗选择「系统默认浏览器」，点击「导出回传扩展」。
2. 在平时使用的浏览器配置加载刚导出的目录。Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`，开启开发者模式并选「加载已解压的扩展」。Firefox 或 Zen 打开 `about:debugging#/runtime/this-firefox`，选「临时载入附加组件」并打开目录内的 `manifest.json`。本地 Firefox 扩展未签名，重启浏览器后需要重新加载。 [Chrome 本地扩展加载说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world) · [Firefox 临时载入说明](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/)
3. 刷新应用打开的登录标签页，首次访问该 VPN 网关时允许扩展回传。若常用配置是浏览器的另一个用户，选「复制登录链接」，在那个用户配置里粘贴。

回传规则只绑定工作台打开的标签页和该次连接的网关。单次链接五分钟内有效。退出连接后，原链接无法向工作台提交票据。

系统默认浏览器的回传扩展 1.2.0 支持登录后和独立打开官方资源页，只向本次已授权网关写入连接会话。已经加载过旧扩展的用户需重新导出并刷新扩展。临时浏览器方式不需要扩展。

## aTrust 授信设备管理

Windows 单文件版内置设备管理。选中已登录的 aTrust 线路，直接点击主界面上的「授信设备管理」，无需断开 VPN。窗口复用该线路已保存的登录状态，设备管理请求不会主动停止或重启连接核心。

2.1.0 修正版保持原版核心的认证请求格式，在新认证完成或确认有效会话后，再尝试上报本机电脑名称、Windows 版本和架构。设备信息更新失败只记录提示；登录所需的校验失败仍会正常阻止连接。保留当前设备唯一标识，网关是否更新历史设备显示，以设备管理刷新后的服务器结果为准。

若看到 `reportEnv failed with code 10000008`，表示接口签名校验失败。2.1.0 初次构建曾修改协议平台声明和登录环境数据，造成这一兼容性回归；请替换为最新修正版，无需更换 CAS 登录方式或再次清理登录缓存。

- 列表显示设备名称、系统、最近登录时间、登录 IP 和在线状态；本机已在列表中时标注「本机」，选中一行可核对完整设备标识。
- 有可用名额时，点击「添加本机为授信设备」。本机已经授信时不重复提交。
- 本机未授信且名额已满、服务器允许自助绑定时，选择一台不再使用的旧设备，点击「解绑并添加本机」。确认框会写明旧设备标识和两项变更，软件按网关的换绑流程提交，随后刷新列表核对旧设备移除、本机授信两个结果。
- 本机已授信时，可以使用「解绑所选设备」单独移除旧设备。不会自动选择设备、连续尝试其他标识或在失败后改用另一种变更操作。服务器记录或换绑条件已变化时会先要求刷新。
- 解绑可能使原设备被网关注销，原设备下次使用可能需要重新认证或申请授信。解绑本机可能中断本机的 VPN 连接，确认框会提示。
- `75500311` 表示授信数量已达上限；设备配额、自助绑定和解绑权限由服务器决定。无法自助处理或需要审批时，按提示联系管理员。
- 登录过期时先关闭窗口、重新连接完成认证，再回来操作。请求超时或服务端只完成部分变更时，按刷新后的实际状态处理，不连续重复提交。网关要求额外认证或审批时不会显示为已完成；当前窗口尚不支持继续额外认证。授信成功仍不代表永久免登录，后续认证由网关策略决定。

## 配置与并行会话

- `Profile/DisplayName` 用作界面名称，可以用中文。重命名保留 INI 文件标识和登录缓存。已有深信服配置通过 `ZJUConnect/Protocol` 识别，无需重建。其他协议的旧配置文件保留在原目录，工作台会隐藏它们。
- 每条配置使用自己的认证流程、核心进程和代理端口。Windows 内置核心为每条开启 TUN 的配置分配独立网卡，网段互不重叠时可以并行。网关认证后若下发相同的虚拟 IP 或重叠的内网网段，应用会阻止新增连接。DNS 劫持一次由一条连接使用。若 Clash TUN 已占用相同的 Fake IP 网段，应用也会提示冲突。
- 同一配置的虚拟网卡被占用、TUN 与 TCP 隧道模式同时开启，或代理端口发生冲突时，应用会提示并阻止启动。关闭 TUN 的配置可通过各自的本机代理并行连接。使用原版 zju-connect 或其他系统时，工作台仍沿用单条 TUN 连接的限制。
- `--profiles-dir` 可指向独立的配置目录，也可用 `--config-path` 临时指定一个 INI。

## Windows 进程名称

主窗口标为「主界面 - EZ4Connectpro」。每条活动线路使用独立的「EZ4Connectpro · VPN 连接核心」进程；「EZ4Connectpro · 运行文件管理」等待主界面结束后清理便携运行文件。

便携启动器完成交接后退出，运行文件管理与 VPN 核心由主界面创建，归属同一棵进程树。它们仍各自拥有独立 PID，便于区分界面、连接和清理功能。

## Windows 防火墙提示

网络核心及 Wintun 保留在 `%LOCALAPPDATA%\EZ4Connectpro\cores\core-<内容摘要>`。相同核心和驱动重启时复用同一路径，并在启动前验证文件；旧版缓存不再被进程占用时才清理。界面和 Qt 库仍临时展开，不重复保存一份连接核心。

首次运行或核心内容更新后，Windows 仍可能询问网络权限。程序不会关闭防火墙、添加公共网络通用放行或改动组织策略。截图中的“此设置由你的组织进行管理”需要管理员处理相应策略；固定路径解决的是随机临时路径造成的重复识别。Windows 防火墙的应用规则按完整可执行文件路径匹配。 [Microsoft 防火墙规则说明](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules)
